# v2.2.0

2026-11-17。复盘的简易评估从 v2 价值头换成 alpha-beta 小预算搜索，
与深度评估同一条实现、同一口径。

## 这一版做了什么

- 简易评估（fast）从「一次 v2 价值前向」改成跑一次小预算搜索：预算是
  普通档去掉噪声，派生自现有档位、不在档位表里另立条目。
- 简易与深度评估的剩余时间估算统一按节点预算 / 吞吐粗算；
  v2 单次前向耗时在复盘链路上的传递（`evalMs`）全部删除。
- 复盘状态与导入标注的「网络估值」改为「快速搜索」，确认弹窗同步。
- `client.evaluate` 与 worker 的 evaluate 消息通道保留：开局应手的 policy
  排序仍然走这一次前向（policy 与 value 同源产出），复盘只是不再消费它的 value。

## 为什么换掉 v2 价值头

v2 的 value 训练标签是自对弈**终局胜负回传到每一手**：开局局面的标签就是
「那局谁赢了」。freestyle 黑必胜加上自对弈白棋的高崩盘率，开局段（黑行棋）
的标签几乎全是黑胜——网络忠实学出「开局黑≈必胜」。这个训练目标在开局段
本来就没有信息，标签再强也救不了，只能换数据源。

深度评估走搜索，开局贴着基率（教师数据黑行棋均值 0.554，开局 55 开附近）。
于是同一局面出现「深评 50 / 简评 100」的矛盾值。预览曲线的用途决定了它的
两条硬要求：同一条曲线内自洽、与深评相关——v2 价值头两条都不满足。

## 参数为什么取这个值

- **普通档为基底**：简易评估是秒级的预览曲线，预算取中档。更浅（简单档
  depth 2）中局抖动大，活三级威胁在 depth 2 内看不全；更深就抢了深评的定位。
- **深度取偶数**是既有约定：奇数深度停在「我刚落子、对手未应」的位置，
  系统性偏乐观。
- **noise = 0**：曲线要可复现、相邻两手才有可比性。抖动是难度档的手感参数，
  不是评估参数。
- **不新建档位**：「普通档去噪声」一句话就能说清的派生值，进档位表只会
  让读者以为多了一档难度。

## 影响面

- 评级不受影响：仍然只有两端都是深评的手才评级。换源之后「跨估计器作差
  不可解释」这条原始理由不再成立，但「浅搜索与深搜索的差同样不可解释」
  取代了它，规则保留。
- 记录格式不变：`quality` 的 `fast` / `deep` 枚举与 header 字段全部不动；
  旧 JSONL 的 fast 值按记录原样还原，导入不受影响。
- 简评仍然不给最佳着、不给 Top、不参与汇总，开局段照旧只记录估值。
- 简评与深评的叶子层相同（λ=1 叶子网），中局两条曲线方向一致、幅度随
  搜索深度可能略浅；开局段一致贴基率。
