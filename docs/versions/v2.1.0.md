# v2.1.0

2026-11-16。叶节点估值从手写的形状公式换成一个蒸馏自教师网络的小型 MLP，
权重以 int16 定点随包下发；旧评估保留为降级路径。

## 这一版做了什么

- 新增 `src/game/leaf/`：`features.ts`（30 维特征）、`net.ts`（int16 定点前向）、
  `blend.ts`（logit 空间的融合）、`evaluator.ts`（新旧评估的接缝）。
- 搜索的四处叶子取分从 `EvalCache.score()` 改成 `LeafEvaluator.score()`；
  缺省仍由旧评估实现，网络不在时行为与 2.0.0 逐位相同。
- `public/models/leaf-v1.bin` 2.2 KB，随包下发，不走 ONNX Runtime——
  它是一个 30→24→12→1 的全连接网，纯 TypeScript 直接跑整数矩阵。
- 对局记录头新增 `evalVersion` / `leafHash` / `lambda`，写的是**实际生效**的值：
  权重没加载成功时是 `hand-2.0.0` / `null` / `0`，而不是配置里的。
- 权重下载失败或与配置里的 SHA-256 不符时退回手写评估，搜索照常完成。

## 特征

30 维，全部从 `EvalCache` 的增量计数读，不扫盘：

| 段 | 内容 |
|---|---|
| 0–11 | 双方成五 / 活四 / 冲四 / 活三 / 眠三 / 活二的计数，按各形状的频次上限归一化 |
| 12–15 | 四个方向上的「己方威胁分 − 对方」/2500，**按值降序排序后输出** |
| 16–21 | 双方位置分 /1000、棋子数 /225、前沿空点 /225 |
| 22–27 | 组合指示：活四、四三、双活三，双方各三项 |
| 28–29 | 阶段（总手数 /225）、先后手（绝对颜色） |

方向集中度的四维要排序，是因为网络不做数据增广：旋转与翻转只会置换方向，
排序后输入向量在 8 种对称下不变。先后手那一维是**绝对颜色**、不随视角对调，
因为 freestyle 黑必胜，基率不对称必须让网络看得见。

## 网络与量化

- 三层全连接，激活是 CReLU（截断在 127/64）。
- 权重 int16 ×4096、特征 int16 ×8192、激活以 1/1024 为尺度、偏置 int32，
  三层移位 15/12/12，**移位一律四舍五入**。
- 走定点而不是浮点，理由不是速度：JS 没有真正的 fp32（`Float32Array` 只负责存，
  运算仍是 double），浮点实现既无法与训练端的 float32 逐位对齐，也会随引擎与平台抖动。
  定点给出一个精确规格，「上线的网就是训出来的网」才是可证的。
- 尺度是照实测的激活量级选的。最初按 1/64 设计，但训练出的隐藏激活是 0.2 量级，
  1/64 等于只用十几个格子表示它；加上裸移位的单向截断逐层累积，
  fp32 与定点的 logit 差到 0.42。改成 1/1024 并四舍五入后差 0.017。
  截断上限仍是 127/64，与训练时的 CReLU 同值——放宽等于把训练时被压掉的激活放出来。

## 三个标定常数

旧评估分换 logit、先后手偏置、新旧信任度，三个数按顺序在对教师胜率的最小化里拟合：

```
u_o = 2·s_o / K + b·parity            parity：黑先 +1、白先 −1
u   = (1 − λ)·u_o + λ·u_n             u_n 是网络头的 logit
s   = round(2500 · u / 2)             输出刻度
```

- **K = 5000**：旧评估专属尺度，回答「多少分算一个 logit」。那个 2 不能丢——
  `0.5 + 0.5·tanh(x) = σ(2x)`，分数与 logit 之间差一个 2 倍。
- **b = 0.15**：黑先基率。旧评估空盘给 0，换胜率就是 0.5，缺的正是这一项。
- **λ = 1**：全用网络。标定给出 1.0，与「网络特征已经包含旧评估的全部信息」一致——
  30 维里就有双方六种形状计数与位置分，旧评估在这之上加不出新信号。

输出刻度固定用 2500（`toWinRate` 的分母），不使用 K。这一条是刻意的：
`noise`、`MOVE_MARGIN`、`GRADE_LOSS`、`SCORE_CLAMP` 全是按那个刻度写的，
若拿 K 当输出尺度，λ=1 时所有分数会整体放大 K/2500 倍，弱档抖动、候选门控、
评级阈值会一起静默改变。代价是 0<λ<1 时分数相对 λ=0 会跳一档；λ 是二值开关，
两端都精确，中间态不提供。

命名上注意：v2.0.0 的档案里把输出刻度也叫 K（=2500），本版的 K 是另一个东西。

## 标定结果

- 训练 6,394 万局面，验证 25,600 局面（教师自对弈，已成五的局面全部丢弃）。
- 网络的 val BCE 0.609，旧评估同一批数据上 0.674；分黑白几乎对称（0.608 / 0.609），
  ECE 0.008。
- 量化对拍：在同一批特征上，定点的 logit 与 fp32 的最大差 0.017。

## 成本

叶子评估从「读几个现成的计数器」变成「算 30 维特征 + 1020 次乘加」。
前向占了九成以上，特征与融合各占几个百分点。

按设计预算（每次 ≤2 微秒、节点吞吐跌幅 ≤20%）复核过，落在预算内；
节点数按老预算不变，没有重推档位参数。前向的成本已经压到「每个乘加约等于一次
读内存再加」——这基本是 JS 的上限，再快只能改网络结构。

## 回退

`EVAL_CONFIG` 里 λ=0 即回到手写评估，与 2.0.0 逐位相同（有单测锁）。
权重缺失、hash 不符、解析失败，三条路都自动落到 λ=0，控制台一条 warning，不阻塞对局。
记录头的 `lambda` 写实际值，所以「这局到底用的哪套」事后可查。

## 已知问题

- **强度没有对局验证过。** 等节点 SPRT（λ=1 vs λ=0，200–600 局、分黑白）与
  影子模式都没跑。25 个战术局面在 λ=1 下命中率仍是 100%，但那只覆盖强制线，
  不覆盖中局战略判断。
- `GRADE_LOSS`（0.05 / 0.10 / 0.20）没重标。输出刻度没变，按理不受影响，
  但评估分布变了，复盘评级的松紧会有漂移。
- 权重文件与引擎的量化常数是两处硬编码的同一组值，靠加载时校验移位来对齐；
  改口径必须同时改训练导出与 `net.ts`，并重新生成对拍基准。
