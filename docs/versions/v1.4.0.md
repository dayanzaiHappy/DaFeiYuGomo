# v1.4.0

2026-11-12。新增只读复盘屏与 JSONL 导入导出；五档搜索预算整体下调约 25%，深评使用困难档去随机。搜索主循环、战术层与模型未改。

## 这一版解决什么

棋力在 1.3.0 已经够用，但「为什么输」只能靠回忆。复盘把整局拆成每手的估值、评级与规则标签；简易评估只做一次前向，深度评估才跑 MCTS。

同时把 `sims` 首项从 40 降到 30：1.3.0 的梯度偏高，整体压低一档比只动简单档更干净。

## 估值与评级

`value` 是行棋方视角，人类视角要翻：

```text
humanValue[i] = points[i].player === humanColor ? moverValue[i] : 1 - moverValue[i]
```

双方都评，`human` 只决定措辞与汇总分组。UI 写「估值」不写「胜率」：模型 `value` 未校准。

落子后的值取自对手视角，损失必须先翻回来：

```text
loss(p) = max(0, moverBefore + moverAfter - 1)
```

写成 `before - after` 会把终局的制胜手算成「损失 78%」。

### 开局段不评级

`OPENING_PLIES = 2`：前两手只记估值，不评级、不打标签、不给最佳着，也不进汇总。AI 执黑的首手固定天元、空盘搜索只有天元一个候选、一两颗子时 top-1 是噪声，这三件事都让前两手没有评估价值。只清 `grade` 不够——`gradeOf` 在 `bestMove` 为空时会退回按损失评级，所以 `bestMove / top / tags` 要一起清；记录写 `opening: true`，汇总单独计数。

### 评级

只在深度评估时评级，双方都评：

| 条件 | 评级 |
|---|---|
| `move === bestMove` | 最佳 |
| `loss >= 0.20` | 败着 |
| `0.10 <= loss < 0.20` | 失误 |
| `0.05 <= loss < 0.10` | 不精确 |
| `loss < 0.05` | 尚可 |

标签优先于估值：`missedWin` / `missedBlockFive` 直接判败着，`missedBlockOpenThree` 至少升到失误；已经是「最佳」的不因标签降级。阈值在 `GRADE_LOSS`，单位是估值损失，不是校准后的胜率损失。

### 规则标签

`judgeMove`，纯规则零推理：

| 标签 | 条件 |
|---|---|
| `missedWin` | 自己能一手成五却下了别处，且这手不是造四 |
| `missedBlockFive` | 对方恰有一个成五点，没挡 |
| `goodBlock` | 挡住了唯一的成五点，或堵住活三的延伸点 |
| `goodOpenFour` | 这手造出活四 |
| `missedBlockOpenThree` | 对方有活三延伸点，没堵，且自己也没冲四 |

自己成五不判漏，对方已有 ≥2 个成五点不补刀；自己冲四视为对攻。标签只属于深评。

## 评估档位

| 模式 | 每个局面 | 输出 |
|---|---|---|
| 简易评估 | 1 次 `evaluate` | value |
| 深度评估 | 82 sims | value + 最佳着 + 评级 + 标签 |

深评展开困难档去随机：`{ ...SEARCH_PROFILES.hard, temperature: 0, noise: null }`。困难档自带 τ = 0.3、ε = 0.03，不覆盖就不是复盘。

- 82 / 20 / 2 / 5，每候选 4.1 次；换档的收益是候选更宽、战术层更硬，不是每条线更深。
- 每个局面都评：只评人类回合会拿深评的 before 和快速的 after 相减，两种估计器混用。
- 终局点是确定值（1 / 0 / 0.5），不送网络；简易评估进屏自动跑，深评由按钮触发并可停止。

## 交互约束

- 棋盘提示取选中那一手的 Top-1 替代，不是当前局面的下一手；取下一手会让棋盘比详情多走一步。开局段、简易评估、本来就是最佳、最佳点即落子点，这四种情况不画。
- 「正确着法」只改渲染，历史、曲线、评级、汇总仍是原局；返回时走反向动画。

## sims 调整

```ts
sims = round(30 * (√e)^n)   // n = 0,1,2,3,4
```

| 档位 | 1.3.0 | 1.4.0 | 每候选访问次数 |
|---|---|---|---|
| 简单 | 40 | 30 | 5.00 → 3.75 |
| 普通 | 66 | 49 | 5.50 → 4.08 |
| 困难 | 109 | 82 | 5.45 → 4.10 |
| 地狱 | 179 | 134 | 5.59 → 4.19 |
| 提示 | 296 | 222 | 6.17 → 4.63 |

- `rootLimit` / `forcedPlies` / `vcfDepth` / τ / ε 不动；`SIMS_BASE` 与 `SIMS_RATIO` 提成常量，之后试 √π 只改一行。
- 测试的「每候选至少 5 次」改成 3.5 并要求沿 easy→hell 单调不减；简单档 3.75 是有意的，不是回归。

## JSONL 记录

每行一个对象，导出当前局，也可从首页读回：

```jsonl
{"type":"header","schemaVersion":1,...}
{"type":"move","ply":5,"player":1,"move":112,"human":true,"quality":"deep","moverBefore":0.55,"moverAfter":0.53,"humanBefore":0.55,"humanAfter":0.47,"loss":0.08,"grade":"inaccuracy","tags":[],"bestMove":113,"top":[{"move":113,"visits":18,"value":0.62}],"fast":{"value":0.51}}
{"type":"hash","algorithm":"sha256","value":"..."}
```

- `moverAfter` 是落子后轮到的一方的估值：示例里黑棋落子后是白方 0.53，黑方 0.47，损失 0.08。
- `quality` 说明 `mover*` 来自网络还是搜索；开局段没有 `top`，`quality` 仍按深评写，不要从 `top` 反推。
- `fast.value` 是网络原始输出，深评覆盖 `mover*` 后仍然保留。
- 开局段写 `opening: true`，此时 `grade / tags / bestMove / top` 为空。
- header 的 `reviewProfile` 记录预算（`82/20/2/5`）；`modelHash` 是 ONNX 字节的 SHA-256，Worker 加载时算一次。
- `recordHash` 对 `header + moves` 的规范化 JSON 算 SHA-256，`hash` 行不参与；它是完整性校验，不是防伪。

## 导入与回放

首页「导入对局」读 JSONL，`parseRecord` 校验后直接进复盘屏，不重跑 AI。

- 曲线、评级、Top-1、正确着法都由 `moverBefore` / `moverAfter` 重建；评级与标签直接映射记录，不按当前规则重算。
- 导入记录只读：评估与导出禁用；返回按钮回首页。
- 兼容没有 `opening` 字段的早期记录；`fromRecord` 挡住难度非法、`result` 非法、空棋谱、`ply` 不连续、黑白不交替、落点越界或重复。

## 这一版不做什么

- SGF、分享链接、跨会话存档、PvP 复盘。
- 单点提示档精评、实时点评、accuracy 校准；也不做胜 / 和 / 负三分类，模型只有标量 value。
