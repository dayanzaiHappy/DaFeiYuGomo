# v1.3.0

2026-11-11。相对 1.2.0 的一次搜索质量修复：**架构不动**（仍是 v2 网络 + 顺序 MCTS），改的是候选、选择公式、战术兜底和候选生成。

## 这一版解决什么

1.2.0 的四档参数是按「网络给每个点打分」的假设标定的，但中局候选常在 150 个上下，而地狱档只有 179 次模拟——平均每个候选被访问 1 次出头，搜索退化成「给每个点评一次分」。同时多数模拟停在 1~3 层，冲四、活三这类要 4~6 层才见终端的战术读不到。表现就是「活三不堵」「能赢的局赢不下来」。

对应六项改动：

| # | 改动 | 收益 | 落点 |
|---|---|---|---|
| 1 | 根节点按先验截断候选，叶节点半径 4 收到 2 | 访问次数集中到有希望的点 | `mcts.ts` `shortlist` |
| 2 | 未访问节点估值改标准 PUCT | 消除「越没看过越值钱」 | `mcts.ts` `uctValue` |
| 3 | 叶节点强制解析（成五 / 挡五 / 连四） | 战术不再靠采样撞 | `tactics.ts` `resolveForced` |
| 4 | 根节点 VCF 快检 | 能赢的局一定赢 | `tactics.ts` `vcf` |
| 5 | 根节点先验偏置 | 先验看不上、但战术必要的堵点能排到前面 | `mcts.ts` `applyPriorBias` |
| 6 | `legalMoves` 改邻接表 + 位图去重 | 纯 JS 候选生成开销大幅下降，输出序列逐点不变 | `board.ts` |

第 6 项是实施中发现的：瓶颈不在内存分配，而在候选生成。它零行为变化，可单独回滚。

## 相对 1.2.0 不变的部分

- 模型、输入输出、评估代码未改。
- 四档难度的 `sims`、温度、噪声强度不变；新增的只是三个旋钮 `rootLimit`、`forcedPlies`、`vcfDepth`。
- 简单档不做战术层：`forcedPlies = 0`、`vcfDepth = 0`、λ 关闭（λ 挂在 `forcedPlies > 0` 上）。
- 搜索版本号从这一版起显式写成 `mcts-1.3`，与模型版本正交：换模型不改它，改公式 / 候选 / 战术才改它。

## 顺带修掉的问题

同一局面点两次提示、建议不一样。1.2.0 的提示档靠默认值凑出「无噪声、无温度」，实际并未显式关闭。这一版把提示作为第五档写进参数表，`temperature = 0`、`noise = null` 都写死，并让提示缓存键包含引擎与模型版本、根 / 叶半径和四个搜索参数——升级后旧缓存自然失效。

## 模型与推理

| 项 | 值 |
|---|---|
| 版本 | v2，b6c96，fp32（`AI_CONFIG.modelVersion = 'v2-b6c96-fp32'`） |
| 文件 | `public/models/model-v2.onnx`，构建时原样进 `dist/models/` |
| 输入 | `planes[1, 2, 15, 15]`：平面 0 为己方子，平面 1 为对方子 |
| 输出 | `policy[225]`（每个交叉点的先验）、`value[1]`（当前行棋方胜率） |

棋盘 15×15，`move` 是 `row * 15 + col` 的一维下标，天元是 112。网络只给「这一步有多好」和「现在谁占优」，不含任何规则知识，不能成五、挡五这类判定全靠 `tactics.ts`。

推理要点：

- `onnxruntime-web` 跑在 Web Worker 里，主线程只发请求收结果（`src/ai/client.ts` ↔ `src/ai/worker.ts`）。
- 初始化时各测一次 WebGPU 与 WASM 的单次评估，取更快的后端；测不出来或初始化失败就回退 WASM。
- GitHub Pages 没有 COOP/COEP，`SharedArrayBuffer` 不可用，所以 WASM **固定单线程**。
- 纯 JS 的搜索开销与单次推理相比是小头，所以优化优先级始终是「减少模拟里的无效计算」，而不是压推理耗时。

## 搜索

顺序 MCTS，一次模拟走一条路径到底，没有并行、没有批量评估。

- **选择**：PUCT。`Q + cPuct · P · √(N+1) / (1 + n)`，`cPuct = 1.5`，`C_FPU = 0`。
  - 未访问节点的 Q 取父节点自身的价值 `Q0`，不用「乐观常数 0.5 + 探索项」。1.2.0 的写法让未访问节点的估值恒大于任何已访问节点的 Q（Q 落在 [0,1]），搜索被迫横向铺开。
  - `C_FPU = 0` 即标准 PUCT，公式见 AlphaZero（Silver 等，2017）。要开 FPU 得注意：惩罚尺度由先验质量决定，先验来自小网，越偏锁得越快；四档又都带根噪声，按 KataGo（Wu，2020）的口径不该启用。
  - 探索项分母用 `1 + n` 而不是 `√n`：未访问节点分母为 1，不会出现 0 除法，也不会让所有子节点并列 0。
- **候选**：根节点半径 4，叶节点半径 2。任何成五、挡五、造四的落点都与已有棋子相邻，2 格足够叶层；根层放宽是为了不漏掉远端的开局点。
- **根候选截断**（`shortlist`）：先按归一化先验取「不低于第一名 5%」的点，再取名次前 `rootLimit` 个，两道取交集；然后并上战术必选点，最后按 `move` 升序排列。
  - 只用名次，政策平坦时会把噪声点全收进来；只用阈值，政策尖锐时可能只剩一两个点。
  - 必选点是安全网：先验不回答「哪必胜」，纯按先验截断会裁掉唯一能赢或必须挡的点。
  - 排序固定按 `move` 升序，保证同一局面的候选序列可复现。
- **先验偏置**（`applyPriorBias`）：在候选池上做 `softmax(log p + b)`，只在根节点做一次，详见下文战术层。
- **叶节点**：先做强制解析（只沿唯一应手证明胜负），判不出来才调网络；有活四威胁的一方再补一个估值下限。
- **回传**：值以叶节点视角算，沿路径按「轮到谁」翻转累加。

### 随机性

两处，都是为了让四档难度「强弱有别、但不呆板」：

1. **根节点 Dirichlet 噪声**：`p' = (1-ε)·p + ε·η`，`η ~ Dir(α=0.1)`，α 固定。
   支持集先过三道闸：先验不低于 top1 的 50%、到上一手的切比雪夫距离 ≤ 2、按先验降序取前 `topM` 名。支持集小于 2 个点时直接跳过——单点 Dirichlet 恒为 1，只会强化自信，等于没随机。
2. **按 visits 采样**：在根节点 visits 前 3 名里按 `visits^(1/τ)` 加权随机；`τ ≤ 0.05` 退化为取访问最多的一手。提示档正是靠这个把 τ 推到 0，同一局面两次提示结果一致。

ε 与 τ 逐档递减，见下文档位参数。

### 开局

玩家执黑、Bot 执白时，白棋第一手**只做一次 policy 前向，不跑 MCTS**：

- 候选集：玩家第一手切比雪夫距离 ≤ 2 的空点。
- 评分：`S = 0.50 · π̂ + 0.30 · a + 0.20 · c`。`π̂` 是 policy 在候选集内归一化，`a` 是贴近玩家程度（相邻 1、隔一格 0.5），`c` 是靠近天元程度（天元 1、角落 0）。
- 在评分前 3 名里按分数加权随机。
- 模型不可用时退回 `S = 0.65 · a + 0.35 · c`，此时不需要推理。

空盘不单独处理：`legalMoves` 在没有棋子时直接返回天元 112，搜索只有一手可选，等于必下天元。

其余局面 PvAI 与提示共用同一套规则、评估和搜索代码，只有参数档位不同。

### 提示

- 提示是**第五个档位**，不是额外功能：`sims` 最高、`rootLimit` 最大、战术全开，但 `temperature = 0`、`noise = null`。
- 结果按「引擎版本 + 模型版本 + 根 / 叶半径 + 提示档四个参数 + 行棋方 + 局面」做 LRU 缓存（`src/game/hint-cache.ts`，上限 32 条）。难度不参与缓存键：提示固定走提示档，把难度放进去只会让「切一次难度、提示缓存全失效」。
- 解释文案由 `src/game/explain.ts` 生成，只描述棋型与坐标，不调用任何在线模型。

## 战术层

小网络只在「像人一样哪儿好」这个粒度上准，四件事它做不到：判断一手是不是已经赢了、判断对方是不是挡不住、证明强制线路、把先验看不上的必堵点排到候选前面。战术层就是补这四个洞，全部是确定性规则，不引入新依赖。

代价从低到高排列。开关不统一：候选并集跟着 `rootLimit` 走，先验偏置、强制解析、威胁修正挂在 `forcedPlies > 0` 上，VCF 独立由 `vcfDepth` 控制。

### 一、根节点 VCF 快检

`tactics.ts` `vcf(board, player, depth, nodeLimit = 20000)`，在搜索开始前跑一次：只靠连续冲四能否取胜。命中直接把这一手作为结果返回，一次模拟都不跑。思路来自五子棋的威胁空间搜索（Allis 等，1993），这里只保留冲四这一条强制线。

每条线路都要求对方应手唯一：

- 我落子后有两个成五点 → 对方挡不住，胜；
- 只有一个成五点 → 对方只能挡，递归下去；
- 对方自己能成五 → 这条线作废（他会先赢）。

因为从不「猜」对方的应手，所以不会误判。代价是只覆盖冲四这一条强制线，判不出来就老老实实跑 MCTS。节点数超过上限即放弃，避免在复杂局面拖慢正常搜索。

深度按档位给 0 / 2 / 5 / 7（简单档不做）。这是「层数」不是「冲四次数」，一级就是一手。

### 二、根候选并集

`forcedMoves` 产出三类点，无条件并进根候选，不受先验阈值和名次上限约束：

1. 我能一手成五的点；
2. 对方能一手成五、我必须挡的点；
3. 对方「下一手能造活四」的点，也就是活三的两个延伸点。

先验只回答「哪儿像好棋」，不回答「哪儿必胜」。候选截断如果不并上这组点，会裁掉唯一能赢或唯一能挡的着法，而且极难复现——同一局面换个温度就复现不出来。

第三类只保证「上场」，不保证「被选中」：堵哪一头、要不要先走自己的进攻，交给搜索判断。如果像成五点那样强制，就会出现「自己有四可以赢，却被逼着去堵活三」。

VCF 首着不在这组里——根节点已经先做过快检，未命中说明不存在这样的首着，并进来只是重复搜索。

### 三、根节点先验偏置

`mcts.ts` `applyPriorBias`，只在根节点做一次：

```text
p' = softmax(log p + b)
b  = (λ / W) · [score + τ · 1{score ≥ τ}]

λ = 2，W = 1000（成五分），τ = 200（活四分）
score = max(攻, 防)，档位：成五 / 活四 / 冲四 / 活三 = 1000 / 200 / 80 / 40
```

- 攻防读同一张表：`threatScore` 取「我这手造出什么」和「我这手堵掉对方什么」的较大者。堵掉对方活三和自己造活三同样值 40，因为两者改变的是同一个威胁，不需要另发明一套防守权重。
- 分值与 `λ` / `W` / `τ` 直接取自 Li 等在 9×9 五子棋上的做法（`b = (λ/W)·[r + τ·1{a ∈ M}]`，λ = 2、W = 1000、τ = 200，档位同表）；这里只是把同样的偏置搬到根节点的候选池上。
- 超过 τ 的招式另加一份 τ，作用是让「必须应」的着法明显压过「等价但不必应」的着法，而不是把两者拉开固定比例。
- 只在根节点做。叶层每层都加等于把偏置乘以深度，会把网络判断彻底盖掉。
- λ 的标定方法固定：拿一批「先验看错活三」的真实局面，看命中数随 λ 的变化。λ = 1 拿走大部分收益，λ = 2 再进一步，λ ≥ 4 开始盖过网络判断、退化成硬规则，所以取 2。改 λ 请重跑这一组局面，不要凭手感调。

### 四、叶节点强制解析

`tactics.ts` `resolveForced(board, player, maxPlies)`，MCTS-Solver 的最小版本（Winands 等，2008）。每个叶节点先判一次，只沿「唯一应手」走：

1. 我能成五 → 我胜（1）；
2. 对方有 ≥ 2 个成五点 → 挡不住，我负（0）；
3. 对方恰好 1 个成五点 → 只能挡，挡完交换视角继续；
4. 其他 → 未解析，返回 `null`，交回网络估值。

不做全宽搜索，所以不会误判；代价是只能证明强制线，判不出来就是判不出来。层数按档位给 0 / 1 / 2 / 3，即最多连续看几步强制应手。

返回的是「轮到我的胜率」，不写 `node.winner`：`winner` 的语义是「盘面上已经有人连成五」，两者混用会让选择阶段的终局判断变得含糊。

### 五、叶节点威胁修正

```text
if 轮到走的一方有活四威胁（下一手能造活四）
   且 对方既不能成五、也没有活四威胁
   value = max(value, 0.85)
```

这是**估值下限**，不是胜负判定：0.85 只表示「明显占优」，不等于必胜。它解决的是稀疏局面下网络给不出信号的问题——叶节点经常只访问过一两次，Q 接近 0.5，有活四的一方看起来和没有一样。这条规则把「有活四」和「没活四」在数值上分开，搜索才会往这条线上多走几次。

门槛取「对方既不能成五也没有活四」是因为再往上就是对方先赢了，这时候抬估值只会把搜索引向错误方向。

### 开关关系

| 项 | 简单 | 普通 | 困难 | 地狱 / 提示 |
|---|---|---|---|---|
| VCF 快检深度 | 0 | 2 | 5 | 7 |
| 根候选并集 | 做 | 做 | 做 | 做 |
| 先验偏置 λ | 0（关闭） | 2 | 2 | 2 |
| 叶强制解析层数 | 0 | 1 | 2 | 3 |
| 叶威胁修正 | 不做 | 做 | 做 | 做 |

候选并集是唯一对简单档也生效的一项：它只影响「谁上场」，不改变估值口径，成本是每手多扫一遍成五点和活三延伸点。简单档真正关掉的是会不会替玩家做判断——VCF、强制解析、先验偏置、威胁修正都会改变搜索的结论，这些一律不做。

## 档位参数

五个档位是同一套代码的五组参数，全部集中在 `src/game/ai-config.ts` 的 `SEARCH_PROFILES` 一张表里。新增档位只需改表和 `DIFFICULTY_ORDER`。

| 档位 | sims | rootLimit | forcedPlies | vcfDepth | τ | ε | λ |
|---|---|---|---|---|---|---|---|
| 简单 | 40 | 8 | 0 | 0 | 1.0 | 0.10 | 0 |
| 普通 | 66 | 12 | 1 | 2 | 0.6 | 0.06 | 2 |
| 困难 | 109 | 20 | 2 | 5 | 0.3 | 0.03 | 2 |
| 地狱 | 179 | 32 | 3 | 7 | 0.1 | 0.01 | 2 |
| 提示 | 296 | 48 | 3 | 7 | 0 | 无噪声 | 2 |

`λ` 不在表里，由 `PRIOR_BIAS_STRENGTH` 统一给 2，再与威胁修正一起挂在 `forcedPlies > 0` 上——所以简单档这两项都不做，而候选并集仍然生效。

### 模拟次数

```ts
sims = round(40 * Math.pow(Math.E, n / 2))   // n = 0,1,2,3,4
```

40 / 66 / 109 / 179 / 296，约每档 ×1.65。用公式生成而不是手填，是因为 1.2.0 的提示预算 292 就是手填时算错的（应为 296），而这种错在代码里看不出来。

### 四个旋钮各管什么

- **sims**：总预算。决定「能看多深」，但对稀疏局面的帮助远小于候选质量——1.2.0 的教训是 179 次模拟摊到 150 个候选上等于没搜。
- **rootLimit**：根节点按先验保留多少个点，决定「谁上场」。0 表示不截断。它与 `SAMPLE_TOP_K`（在几个里抽）、`hintTopK`（展示几个）是三件事，不要混。
- **forcedPlies**：叶节点强制解析的层数。0 表示不做，同时把先验偏置和威胁修正一起关掉（两者都依赖「能证明强制线」这个前提）。
- **vcfDepth**：根节点 VCF 深度。0 表示不做，与 `forcedPlies` 独立。

### 改参数时的连锁影响

1. **提示缓存**：缓存键包含引擎与模型版本、根 / 叶半径和四个搜索参数。动这几个值必须同步改 `engineVersion`，否则升级后用户会拿到旧局面下的旧建议。
2. **难度顺序**：设置面板的展示顺序与合法性校验都读 `DIFFICULTY_ORDER`，加档位只改这一处，但持久化的旧值要做兜底（非法值回落普通档）。
3. **简单档的边界**：想让它更弱，调 `sims` 和 `rootLimit`，不要打开战术层再调小预算——那会得到一个「偶尔漏杀、偶尔秒杀」的不稳定档位。
4. **噪声支持集**：`topM` 与 `NOISE_MIN_RATIO` / `NOISE_RADIUS` 一起决定噪声落在哪儿。放宽 `topM` 会让 AI 在明显劣势的位置乱走，收紧会让对局每局雷同。
