# UI 实现约束

这几条不是风格偏好，是已经踩过的坑。改动相关代码前先读一遍，否则会出现「功能没坏但界面在抖」的问题。

## 一、随机文案必须走稳定选择

`refreshHintPanel()` 每次 `refreshAll()` 都会跑——切皮肤、开关音效、AI 状态变化都算。任何随机文案必须走 `pickLineStable(命名空间, 词池, 签名)`，用签名做种子。直接 `Math.random()` 取一条，用户会看到「开个音效开关，台词就换一句」。

## 二、提示视图的记忆化不要拆

`buildHintView()` 会被重复调用（重绘、面板刷新、状态栏更新时间），内部用 `WeakMap` 按 `SearchResult` 记忆化。去掉缓存，同一条提示在重绘时会改措辞——搜索结果没变，文案却变了。

## 三、气泡高度靠样式撑住

台词很短，4~12 字。气泡高度靠 `#hint-text` 的 `min-height` 固定住。删掉它，状态在「一句短话」和「两行解释」之间切换时，右侧栏会上下跳。

## 四、两条通道分工

- 气泡：只放**当前状态**（轮到谁、AI 在想什么、这局的建议）。
- Toast：只放**刚发生的事**（悔棋、重开、点错格子、非自己回合）。

不要把瞬时事件塞进气泡：气泡是持久区域，会被下一条状态覆盖，用户看不到。反过来也不要让 Toast 承载状态，它 1.8 秒就消失。

## 五、必杀局面用确定语气

一手成五、必须挡五这类局面，文案强制走确定性分支，不受搜索评分影响。否则会出现「这一步直接连成五子了。局面有点紧，先稳住。」这种自相矛盾——判定和语气来自两套逻辑。

## 六、版本号只有一个来源

版本号在构建期由 `vite.config.ts` 的 `define` 注入 `__APP_VERSION__`，值来自 `package.json`。页脚、关于弹窗、debug 文案都读它，不要在任何地方再写死一份。写死的那一份一定会在某次发版时忘记改。

## 七、移动端手势

棋盘区要阻止页面滚动与缩放手势（`touch-action` + `preventDefault`），否则落子会变成拖动页面；棋盘外的区域保留正常滚动。Canvas 按 `devicePixelRatio` 放大绘制，CSS 尺寸不变，否则高分屏上棋子边缘发虚。
